# YO-DEE Design System — กติกา UI ที่ใช้ร่วมกันทุกหน้า (2026-07-26)

เอกสารนี้คือ "กติกากลาง" ตอบคำถามว่า ปุ่มไหน/สวิตช์ไหน/ช่องไหน ใช้เมื่อไหร่ วางตรงไหน
เพื่อให้ทุกหน้า (แคชเชียร์ + LIFF ลูกค้า) หน้าตาและพฤติกรรมเหมือนกันหมด
หน้าอ้างอิง (reference implementation) = **คูปอง & แคมเปญ** — หน้าอื่นทยอยปรับตามเมื่อแตะโค้ดส่วนนั้น

## 1) สี (จาก brand guide — ดู yodee-brand-palette)

| บทบาท | ค่า | ใช้กับ |
|---|---|---|
| Accent (teal) | `var(--accent)` #1ab3ce | ปุ่มหลัก, แท็บ/ชิปที่เลือกอยู่, ลิงก์ |
| Accent2 (mint) | `var(--accent2)` | ราคา/ส่วนลด, ปุ่มยืนยันจ่าย |
| Navy | `var(--navy)` #284B63 | หัวข้อ, ตัวเลขสำคัญ, ปุ่มรองแบบเข้ม |
| Muted | `var(--muted)` #8A9299 | คำอธิบาย, เงื่อนไข, meta |
| Success | #0f6b57 บน #e1f5ee | สถานะ "เปิด/พอดี/สำเร็จ" (ผ่าน AA แล้ว — ห้ามใช้เฉดอ่อนกว่านี้) |
| Warning | #7a5c00 บน tint เหลือง | "รอ/ค้าง/ใกล้หมด" |
| Danger | #b3283a | ลบ/ยกเลิก/เหตุผลที่ใช้ไม่ได้ |

## 2) ปุ่ม — ลำดับชั้น 3 ระดับ (กติกาเหล็ก: **ปุ่มหลักได้ 1 ปุ่มต่อหนึ่งจอ/การ์ด**)

| class | หน้าตา | ใช้เมื่อ | ตัวอย่าง |
|---|---|---|---|
| `.ok` | teal ทึบ ตัวขาว | การกระทำหลักเดียวของจอ | ส่งถึงลูกค้า, ชำระเงิน, บันทึก(ฟอร์มใหญ่), ใช้(คูปอง) |
| `.ghost` | ขอบ พื้นใส | การกระทำรอง/ทางเลือก | ปิด, แก้ไข, ดูรายงาน, บันทึก(รายแถว) |
| `.danger` | แดง | ทำลายข้อมูล — ต้องมี confirm เสมอ | ลบ, ยกเลิกคูปอง, void |

- ห้ามใช้ `.ok` สองปุ่มเคียงกัน — ถ้าลังเลว่าปุ่มไหนหลัก แปลว่ายังออกแบบไม่จบ
- ขนาดสัมผัสขั้นต่ำ 44px (มองเล็กได้ แต่ hit area ต้องถึง — ดู `.qstep` เป็นตัวอย่าง)
- ปุ่มลิงก์ (ไปหน้าอื่น ไม่ทำอะไรกับข้อมูล) = ตัวหนังสือ teal ลงท้าย `›` เช่น "ตั้งค่าแต้ม ›"

## 3) Toggle vs Checkbox — เส้นแบ่งที่ทำให้เลิกงง

| ตัวควบคุม | class | กติกา |
|---|---|---|
| **Toggle switch** | `.tgl on/off` | เปิด-ปิดการทำงาน และ**มีผลทันทีที่กด** ไม่มีปุ่มบันทึก (เช่น เปิดแคมเปญวันเกิด, เลขนำโชค, เปิด-ปิดคูปอง) |
| **Checkbox** | `input[type=checkbox]` | เลือกรายการ/ตัวเลือก**ในฟอร์ม** ที่จะมีผลเมื่อกดปุ่มยืนยัน (เช่น ติ๊กเลือกลูกค้า, แนบคูปอง) |

ผลที่ตามมา: ทุกอย่างที่เป็น "สถานะระบบ" ต้องเป็น toggle — ห้ามเป็น checkbox ที่ต้องกดบันทึกซ้ำ
ถ้าสถานะถูกคุมจากหน้าอื่น (เช่น "สะสมครบ" ตามระบบแต้ม) **ห้ามโชว์ toggle ปลอม** —
ใช้ป้ายสถานะ (pill) + ลิงก์ไปหน้าที่คุมจริง

## 4) ชิปช่วงเวลา / ตัวกรอง — `.seg`

- กลุ่มปุ่ม preset (`วันนี้ · 7 วัน · 30 วัน · 1 ปี`) ใช้ `class="ghost seg"` และตัวที่เลือก `+" on"` — เลือกได้ทีละหนึ่ง
- วางลำดับเสมอ: **[ชิป preset] → [ช่วงวันที่เอง from–to + ปุ่ม ดู]** — preset ก่อน custom เสมอ
- เลือก preset จะล้างวันที่ custom และกลับกัน (ห้ามให้หัวรายงานพูดสองเรื่อง)
- ตัวกรองข้อมูล (ทั้งหมด/กลุ่ม) ใช้ pattern เดียวกับแท็บลูกค้า (clSegTabs)

## 5) ช่องค้นหา

- อยู่**บนสุดของลิสต์เสมอ** เต็มความกว้าง, `type="search"`, placeholder ขึ้นต้น 🔍 บอกว่าค้นอะไรได้
- ค้นแบบ debounce ~300ms ไม่มีปุ่มค้นหาแยก

## 6) การ์ด / หน้า

- ทุกหน้า back-office: กรอบเดียว `max-width:1100px` (มี rule กลางบังคับแล้ว)
- หัวหน้า: `h1` + คำอธิบายสั้นสีเทา ซ้าย · ปุ่ม "ปิด" (`.ghost`) ขวาเสมอ
- การ์ดย่อยในหน้า: `background:var(--surface); border:1px solid var(--line); border-radius:14px`
- KPI ใช้ `.kgrid` เท่านั้น (auto-fit, มือถือ 2 คอลัมน์)
- ลิสต์ยาว: แบ่งหน้า + ปุ่ม "ดูเพิ่ม (N)" — ห้ามโหลดทั้งตาราง

## 7) ฟอร์ม & อินพุต

- `input` ขนาดตัวอักษร ≥16px (กัน iOS ซูมเอง — ตั้งกลางไว้แล้ว)
- ทุกช่องมี label มองเห็น — ห้ามใช้ placeholder แทน label
- ช่องที่ถูกล็อกเพราะค่ามาจากที่อื่น (เช่น ผูกคูปองแล้ว): `disabled` + พื้น `var(--surface)` ตัว muted
- ผลลัพธ์หลัง submit ตอบทันทีด้วย `toast()` — สำเร็จบอกสั้น, พลาดบอกเหตุผล+ทางแก้
- ปุ่ม submit ต้อง `disabled` ระหว่างส่ง (กันกดซ้ำ) แล้วคืนสภาพเสมอ (`finally`)

## 8) สถานะโหลด / ว่าง / พลาด — ครบสามเสมอ

| สถานะ | รูปแบบ |
|---|---|
| กำลังโหลด | `<p class="muted">กำลังโหลด…</p>` (ลิสต์) หรือปุ่มเปลี่ยนข้อความ เช่น "กำลังรับ…" |
| ว่าง | มีภาพประกอบ + หัวข้อ + คำอธิบาย + (ถ้ามีทางไปต่อ) ปุ่ม CTA — ดู "ไม่พบคูปองที่ใช้ได้" เป็นแบบ |
| พลาด | บอกว่าอะไรพลาด + ทำอะไรต่อได้ — ห้ามโชว์ error code ดิบให้ลูกค้า |

## 9) การ์ดคูปอง (ภาษาเดียวกันทุกที่)

ตั๋วเจาะรู: แผ่นมูลค่าซ้าย (มูลค่าคือรูปภาพ) → เส้นประ + รอยบาก → รายละเอียด → การกระทำเดียว
สีตามชนิด: วันเกิดชมพู · ของขวัญร้านเหลือง · สะสมครบมินต์ · โค้ด teal
ใช้ทั้งใน: กระเป๋าคูปองลูกค้า, หน้ารับคูปอง, (ต่อไป) การ์ด LINE

## 10) พฤติกรรมคูปองฝั่งลูกค้า

- กด "ใช้" จากกระเป๋า → **พาไปหน้าเมนูทันที** คูปองถูก arm ไว้
- ส่วนลด **apply อัตโนมัติเมื่อยอดเข้าเงื่อนไข** — ระหว่างที่ยังไม่ถึง ตะกร้าบอกชัด "ซื้อเพิ่มอีก ฿X เพื่อใช้คูปองนี้"
- รับคูปองจากลิงก์สำเร็จ → กด "สั่งเลย" คูปอง arm ให้อัตโนมัติฝั่งเมนู
- server ตรวจเงื่อนไขซ้ำตอนสร้างออเดอร์เสมอ (ฝั่งจอเป็นแค่ตัวช่วยแสดงผล)

## 11) เช็กลิสต์ก่อนส่งงาน UI ทุกครั้ง

1. ปุ่มหลักมีปุ่มเดียว และเป็น `.ok`
2. toggle = มีผลทันที / checkbox = รอปุ่มยืนยัน — ไม่มีสลับข้าง
3. สถานะ โหลด/ว่าง/พลาด ครบสามแบบ
4. touch target ≥44px, contrast ผ่าน AA (ใช้เฉดจากตาราง §1)
5. ความกว้างหน้า = กรอบกลาง ไม่ตั้งเอง
6. ข้อความ error บอกทางแก้ ไม่ใช่แค่บอกว่าพัง
